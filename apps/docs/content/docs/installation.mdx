Strata ships two ways from one source: as a registry the shadcn CLI installs from, and as npm packages. Both give you the same component files and the same tokens. Every component page has the exact commands.

<Callout tone="info" title="Not on npm yet">
  `@strata/react` and `@strata/tokens` are published in Phase 6. Until then, install from the registry or copy the files by hand. The npm steps below show how the packages will work.
</Callout>

You need React 19 and a bundler that handles CSS Modules — Next.js and Vite both do out of the box.

## With the shadcn CLI

The CLI copies each component’s `.tsx` and `.module.css` into your `components/ui` folder, installs the npm packages it needs, and pulls in any Strata components it uses. You own the code from then on.

<Steps>

### Add the Strata base

The base item installs the house tokens as `styles/strata-house.css` and the `ThemeScope` component.

<PackageCommand dlx="shadcn@latest add {{SITE_URL}}/r/strata.json" />

To start from a tenant’s tokens instead, add `strata-tokens-vela`, `strata-tokens-harbor` or `strata-tokens-qamar` the same way.

### Import the tokens once

Import the token file at your app root — `app/layout.tsx` in Next.js, `src/main.tsx` in Vite.

<CodeBlock title="app/layout.tsx">

```tsx
import '../styles/strata-house.css';
```

</CodeBlock>

The font stacks fall back to system fonts. For the brand’s own type pair, add the Google Fonts stylesheet the CLI prints after the install.

### Add components

<PackageCommand dlx="shadcn@latest add {{SITE_URL}}/r/button.json" />

Components that use other components bring them along: adding `dialog` also adds `button`.

</Steps>

## Add the @strata namespace

Register the namespace once in `components.json` and you can install by name instead of URL.

<CodeBlock title="components.json">

```json
{
  "registries": {
    "@strata": "{{SITE_URL}}/r/{name}.json"
  }
}
```

</CodeBlock>

<PackageCommand dlx="shadcn@latest add @strata/button @strata/dialog" />

The namespace also lets AI coding agents find Strata components through [MCP](/docs/mcp).

## With npm

<PackageCommand add="@strata/react @strata/tokens" />

Import the token CSS once, then wrap the part of your app that should use a theme.

```tsx
import '@strata/tokens/dist/strata.css';
import { Button, ThemeScope } from '@strata/react';

export default function App() {
  return (
    <ThemeScope theme="vela">
      <Button>Continue</Button>
    </ThemeScope>
  );
}
```

`dist/strata.css` holds every tenant, each scoped to `[data-strata-theme="<id>"]`. `dist/<id>/tokens.css` holds one tenant on `:root`, for apps that only ever show one brand.

The package ships TypeScript source and CSS Modules today. In Next.js, add `transpilePackages: ['@strata/react']` to `next.config`; a compiled build that emits plain CSS is planned ([ADR-003](https://github.com/anujpatel06/strata/blob/main/docs/adr/003-styling-css-modules.md)).

## By hand

Every component page has a **Manual** tab with the full source of each file.

1. Install the npm packages the component lists — usually `react-aria-components` and `@tabler/icons-react`; date components also need `@internationalized/date`.
2. Copy its `.tsx` and `.module.css` files into one folder.
3. Copy any Strata components it uses into the same folder. Files import each other as `./button`, so the folder can live anywhere.
4. Load a token file once, from the registry item or `@strata/tokens`.

## Set the theme

Token CSS keys off three attributes on one element — `<html>` for the whole app, or a `ThemeScope` for part of it.

```html
<html data-strata-theme="vela" data-strata-scheme="auto" data-strata-density="compact">
```

See [Theming](/docs/theming), [Dark mode](/docs/dark-mode) and [Density](/docs/density) for what each one does.
