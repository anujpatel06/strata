A Strata theme is generated, not drawn. Six brand inputs go through the theme engine, which builds colour ramps, assigns semantic roles for light and dark, fixes every contrast failure it finds, and writes CSS variables. Components only ever read those variables.

A new brand changes values, never names — so no component knows which brand it renders ([ADR-005](https://github.com/anujpatel06/strata/blob/main/docs/adr/005-token-tiers-and-naming.md)).

## A brand is six inputs

Primary colour, an optional accent, neutral temperature, shape, type pair and default density. This is Harbor’s whole brand:

<TenantBrandJson id="harbor" />

The engine keeps the brand hex exact where contrast allows and moves labels, rings and text first when it doesn’t. Every move is logged in a sentence, e.g. the house brand of this site:

<HouseAdjustments />

To generate a theme yourself:

```ts
import { generateTheme, toCSS } from '@strata/theme-engine';

const theme = generateTheme({
  name: 'Acme',
  primary: '#0f766e',
  neutral: 'cool',
  shape: 'soft',
  typePair: 'technical',
  density: 'comfortable',
});

const css = toCSS(theme, { selector: '[data-strata-theme="acme"]' });
```

Other variables follow the same pattern: `--strata-space-{0…16}`, `--strata-radius-{button,field,container,badge,pill}`, `--strata-font-{heading,body,mono}`, `--strata-font-size-{xs…3xl}`, `--strata-shadow-{raised,overlay}`, `--strata-motion-*` and the density variables. ## ThemeScope

Token CSS keys off `data-strata-theme`, `data-strata-scheme` and `data-strata-density`, and they must sit on the same element. `ThemeScope` puts them there and gives the subtree the theme’s canvas, text colour and body font. Its `locale` prop also sets React Aria’s locale, `lang` and `dir` — see [RTL](/docs/rtl).

```tsx
import { ThemeScope } from '@strata/react';

<ThemeScope theme="harbor" scheme="dark" density="compact">
  <ClaimForm />
</ThemeScope>
```

### How token files are scoped

`toCSS` takes the selector for a theme’s base block and appends the mode attributes to it. The registry’s token files use:

```css
:root, [data-strata-theme="<id>"], [data-strata-scheme]:not([data-strata-theme]) { … }
```

So the file’s tenant is the page default, a named scope can still pick it when several files are loaded, and a scope with only `scheme` or `density` switches modes without naming a tenant. `@strata/tokens/dist/strata.css` scopes every tenant to `[data-strata-theme="<id>"]` only. Details in [Registry](/docs/registry#token-files).

## Several tenants on one page

Scopes nest and sit side by side, each with its own tenant, scheme and density. This site is the example: the chrome uses the house theme on `:root`, and every preview is a `ThemeScope` you can switch between tenants.

```tsx
<div className="compare">
  <ThemeScope theme="vela"><PaymentCard /></ThemeScope>
  <ThemeScope theme="qamar" locale="ar-AE"><PaymentCard /></ThemeScope>
</div>
```

Dialogs, popovers and menus render in a portal at the end of `<body>`, outside any scope. When one opens, it copies the scope attributes, `dir` and `lang` from the element that opened it — so a dialog opened from a Harbor-dark preview is Harbor-dark (<AdrLink n="012" />). Try it: pick a tenant and a scheme, then open the dialog.

## Adding a tenant

1. Create `tenants/<id>/brand.json` with the six inputs, and `content.json` with the tenant’s copy, locale and direction.
2. Run `pnpm tokens`. It fails if any contrast check fails, so a broken theme can’t ship.

That’s all. No component changes, and this site picks the new tenant up on its next build — in the preview toolbar, the tables above and the registry, which gains `strata-tokens-<id>` and `theme-<id>` items.

## Using Strata colours in shadcn/ui

Every theme also exports as shadcn/ui variables. `npx shadcn@latest add @strata/theme-<id>` gives an existing shadcn project a tenant’s palette, light and dark — see [the shadcn bridge](/docs/registry#the-shadcn-bridge) for the mapping and the pairs it doesn’t guarantee.
